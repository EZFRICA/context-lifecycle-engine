# Stating a number in this repository

The research question is the lifecycle value of agents that already exist, and
the deliverable is **architectures with their trade-offs, never a winner**. A
number that does not say what it is conditioned on is the failure this repo
keeps catching in itself.

## Every published figure carries four things

1. **A pinning key**: `(date, commit, embedder_id, model_id)`. A figure without
   one is reproducible by nobody, including its author a month later.
2. **A reproduction command** that actually runs. `space_identity.py` was cited
   as the reproduction of a published figure while crashing with `NameError`
   before its first billed query; `tests/property/test_scripts_resolve.py`
   exists because of that.
3. **The space it was measured in.** Centroids and cosines are only comparable
   inside the space that produced them. `bigquery:gemini-embedding-001:768` is
   a DIFFERENT MODEL from the engine's `google:gemini-embedding-2:768` - cosine
   between them on the same texts is 0.040084 - so every bench figure says so.
4. **What it does not claim.** Each section ends with the limits: corpus size,
   synthetic vs real, upper bound vs estimate, in-sample vs holdout.

## A space is more than a model name

A vector space is `(model, surface, dimension)` and, for a locally-run model,
two more coordinates that change the geometry:

- **quantisation** - fp32, fp16, int8, q4 are different spaces, not sizes of
  one space;
- **prompt/task prefix** - EmbeddingGemma under `task: clustering` and under
  `task: search result` embeds the same sentence somewhere else. Measured on
  the repo's own corpora, the prefix moved F from 0.58 to 0.90, as much as the
  model choice did.

Name all of it in the `embedder_id`, or the figure belongs to a space chosen by
accident.

## The threshold belongs to the space, and is swept, never assumed

`CLUSTER_THRESHOLD_BY_EMBEDDER` carries one value per space (0.6 stub, 0.775
`gemini-embedding-2`, and nothing for a space nobody swept), and
`CALIBRATION_PROVENANCE` carries the sentence saying where it came from. Two
rules follow:

- **A space with no calibrated threshold must not reach a lifecycle decision.**
  Adding an embedder kind means sweeping first and writing both entries.
- **An optimum at the edge of a sweep is not an optimum.** Widen the grid until
  each peak is interior; a peak at the first value measured the grid.

## In-sample is not evidence

`prompt_history_gdg.jsonl` helped choose 0.775, so reading the reference space
at 0.775 on GDG grades it on its own exam. `prompt_history_holdout.jsonl` is
generated by a module that imports nothing from `cle` - that is the
process-independent comparison, and it is the one a verdict rests on. Say which
corpus a figure came from, every time.

## Re-measuring adds a column; it never edits one

A figure is conditioned on the space, the model version, the prompt version and
the date. When any of those change - a model goes GA, a prompt gets a fence, a
quantisation changes - the new run produces a NEW figure beside the old one,
with its own pinning key. Rewriting the old number in place would silently
restate a measurement nobody made. Keep the version in the id that carries it
(`facet-prompt-v1` vs `name-prompt-v2`) so the old figures stay readable.

## Comparing two methods

- Read each at **its own** calibrated threshold. One number applied to two
  spaces measures the number.
- Report **both** purity and completeness (or recall at a matched
  false-positive budget). Either alone rewards a degenerate grouping: one item
  per cluster is perfectly pure, one cluster is perfectly complete.
- Report **agreement** (adjusted Rand index) as well as score. Two methods can
  score alike and partition differently, which is the finding, not a detail.
- The ranking of methods **depends on the error budget** (`docs/FINDINGS.md`
  §6c). State the budget or the ranking is unconditioned.

## The numbers the suite itself guards

- The documented test count in `README.md`, `docs/TESTING.md`,
  `docs/METRICS.md` and `docs/CAPABILITIES.md` must equal what the collector
  reports; adding a file under `examples/` or `tools/` changes it, because
  `test_scripts_resolve` is parametrised over those directories.
- The three test buckets are MEASURED by `tools/buckets.py --check`, not
  counted by hand, and the SCOPE header of every module must agree.
- `tools/mutate.py` decides whether a guard bites. Run it ALONE: it mutates the
  tree in place, so a second pytest reading the same tree reports guards that
  do not exist.
